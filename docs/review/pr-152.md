## Finding

### [P1] Omitted custom-input parent raises `KeyError`

Location: [`graphene_django_cud/mutations/core.py:201`](https://github.com/trmdy/graphene-django-cud/blob/7bcfbd9d908af6d3628a3309821d460f7b164a2a/graphene_django_cud/mutations/core.py#L199-L202)

Graphene's `InputObjectTypeContainer` exposes all declared fields as attributes, so an omitted optional parent appears as `value.owner is None`. Its underlying mapping contains only fields supplied by the caller, however, so it does not contain an `"owner"` key.

The added condition therefore behaves as follows:

```python
if not hasattr(value, "owner") or value["owner"] is None:
```

`hasattr(value, "owner")` is true, then `value["owner"]` raises `KeyError('owner')`. The mutation returns a GraphQL error instead of creating and associating the child.

I reproduced this with a named `CreateNestedCatInput` whose `owner` field is optional:

- `main`: fails with the original `NOT NULL constraint failed: tests_cat.owner_id` bug.
- PR head: fails with `GraphQLError("'owner'")` caused by the new `KeyError`.

The safest correction is consistent with the existing generated-input branch and the semantics of a nested reverse relation:

```python
value[field.field.name] = obj.pk
```

If preserving a supplied parent is explicitly intended, `if value.get(field.field.name) is None:` avoids the exception. In either case, add the named/custom-input regression test to the PR. With the latter condition and the regression test, the complete local suite passed (`111 passed`).

No additional defects were found in the one-file PR diff.
